Corrections apportées à ton DBML

6 problèmes détectés. Les 3 premiers sont critiques (le schéma ne respecte pas le cahier des charges).

1. siege.numero était UNIQUE globalement
Le cahier dit : « le siège 1A existe dans presque toutes les configurations ». Unicité par configuration, pas globale. → Retirer unique sur siege.numero, garder UNIQUE(configuration_id, siege_id) dans configuration_siege.
2. passager.date_naissance manquante
Obligatoire dans le cahier, doit être dans le passé. CURRENT_DATE n'étant pas immutable, un CHECK ne fonctionne pas en PostgreSQL → utiliser un TRIGGER.
3. tarif.date superflue
Le tarif varie selon le segment effectif (qui porte déjà la date). Le champ date permettait d'avoir plusieurs tarifs pour un même (segment, classe), ce qui contredit « tous les billets d'une même classe ont le même tarif ». → Unicité sur (segment_effectif_id, classe_id), supprimer date.
4. billet — mauvaise contrainte d'unicité passager
Le cahier dit « un.e passager.ère a au plus un billet » par segment. La contrainte (segment_effectif_id, configuration_siege_id, passager_id) ne l'impose pas (même passager + même vol + siège différent = OK). → Remplacer par UNIQUE(segment_effectif_id, passager_id).
5. segment_offert — CHECK départ ≠ arrivée manquant
Le cahier impose « forcément différent de celui de départ ». → Ajouter CHECK (aeroport_id_depart <> aeroport_id_arrive).
✓ Points corrects conservés
Modèle / configuration / avion (hiérarchie correcte, largeur_sieges bien modélisée), UNIQUE(segment_offert_id, date), UNIQUE NULLS NOT DISTINCT sur no_fidelite, structure billet → configuration_siege (le siège est bien identifié par sa position dans une config), et l'usage de time + date séparés pour les horaires prévus.

Règles non garanties par le schéma (à mentionner en commentaire)

  • Le siège d'un billet doit appartenir à la configuration de l'avion du segment effectif.
  • Une classe tarifée doit exister dans la configuration de l'avion.
  • La convention « arrivée le lendemain » (arrivee < depart) n'est pas structurelle.

Partie B — Stratégie de requête (sans SQL)

Pour chaque question : tables, jointures, filtres.

1. Avions avec immatriculation, modèle et configuration

Tables : avion, configuration, modele.
Jointures : avion.configuration_id = configuration.id ; configuration.modele_id = modele.id.
Filtres : aucun.

2. Segments offerts entre deux aéroports donnés

Tables : segment_offert, aeroport (×2 alias : départ, arrivée).
Jointures : segment_offert.aeroport_id_depart = dep.id ; segment_offert.aeroport_id_arrive = arr.id.
Filtres : dep.code = 'GVA' ET arr.code = 'YUL'.

3. Classes et tarifs pour un segment effectif donné

Tables : tarif, classe.
Jointures : tarif.classe_id = classe.id.
Filtres : tarif.segment_effectif_id = :id.

4. Passagers avec siège, classe et montant payé (segment effectif donné)

Tables : billet, passager, configuration_siege, siege, classe.
Jointures : billet.passager_id = passager.id ; billet.configuration_siege_id = configuration_siege.id ; configuration_siege.siege_id = siege.id ; configuration_siege.classe_id = classe.id.
Filtres : billet.segment_effectif_id = :id.

5. Sièges encore libres pour un segment effectif donné

Tables : segment_effectif, avion, configuration_siege, siege, billet (LEFT JOIN).
Jointures : segment_effectif.avion_id = avion.id ; avion.configuration_id = configuration_siege.configuration_id ; configuration_siege.siege_id = siege.id ; LEFT JOIN billet sur billet.segment_effectif_id = :id ET billet.configuration_siege_id = configuration_siege.id.
Filtres : segment_effectif.id = :id ET billet.id IS NULL.

6. (bonus) Segments effectifs arrivés avec plus de 30 min de retard

Tables : segment_effectif, segment_offert.
Jointures : segment_effectif.segment_offert_id = segment_offert.id.
Filtres : arrivee_reel IS NOT NULL ET
arrivee_reel > (date + arrivee [ + interval '1 day' si arrivee < depart ]) + interval '30 minutes'.
Astuce : le +1 day gère les vols qui arrivent le lendemain.

Schéma SQL corrigé (extrait)

Le fichier complet airline.sql contient le schéma, les données de test et les INSERT qui doivent échouer.

CREATE TABLE siege (
    id     SERIAL PRIMARY KEY,
    numero VARCHAR(255) NOT NULL          -- PAS de UNIQUE global
);

CREATE TABLE passager (
    id             SERIAL PRIMARY KEY,
    prenom         VARCHAR(255) NOT NULL,
    nom            VARCHAR(255) NOT NULL,
    date_naissance DATE         NOT NULL,
    no_fidelite    VARCHAR(255) UNIQUE NULLS NOT DISTINCT
);

CREATE TABLE configuration_siege (
    id                SERIAL PRIMARY KEY,
    configuration_id  INTEGER NOT NULL REFERENCES configuration(id),
    siege_id          INTEGER NOT NULL REFERENCES siege(id),
    classe_id         INTEGER NOT NULL REFERENCES classe(id),
    UNIQUE (configuration_id, siege_id)
);

CREATE TABLE tarif (
    id                   SERIAL PRIMARY KEY,
    segment_effectif_id  INTEGER NOT NULL REFERENCES segment_effectif(id),
    classe_id            INTEGER NOT NULL REFERENCES classe(id),
    prix                 INTEGER NOT NULL CHECK (prix >= 0),
    UNIQUE (segment_effectif_id, classe_id)   -- pas de champ date
);

CREATE TABLE billet (
    id                       SERIAL PRIMARY KEY,
    segment_effectif_id      INTEGER NOT NULL REFERENCES segment_effectif(id),
    configuration_siege_id   INTEGER NOT NULL REFERENCES configuration_siege(id),
    passager_id              INTEGER NOT NULL REFERENCES passager(id),
    prix                     INTEGER NOT NULL CHECK (prix >= 0),
    UNIQUE (segment_effectif_id, configuration_siege_id),
    UNIQUE (segment_effectif_id, passager_id)
);
