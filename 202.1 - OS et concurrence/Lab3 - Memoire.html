🎯 C'est quoi ce lab ?

Tu as une mini-machine virtuelle avec 4 Ko de mémoire principale et 256 Ko de mémoire secondaire. Le CPU ne voit pas la vraie mémoire physique : il voit une mémoire virtuelle qu'il faut traduire à chaque accès.

Ce lab implémente déjà presque tout : la traduction d'adresse, la pagination à la demande, le swap (échange vers le disque).

🚧 Ce qu'il te reste à faire Implémenter mmap — la fonction qui réserve une nouvelle plage d'adresses virtuelles (comme un malloc).

🧠 La mémoire physique : 4 Ko = 16 frames

La mémoire principale est un tableau de 512 × UInt64 = 4096 octets. Découpée en 16 frames de 256 octets.

Clique sur une frame pour voir son état 👇

🏗️ Layout de la frame 0 (kernel)

La frame 0 est pinnée (jamais swappable) et stocke les structures du noyau :

0x000 – 0x040 · Frame table (16 descripteurs × 4 octets)
0x040 – 0x042 · Free map (16 bits)
0x042 – 0x044 · Kernel break (kbrk)
0x044 – 0x04c · Page map root (L0)
0x04c – 0x100 · Pool non-alloué
⚠️ Ordre d'allocation important Le kernel alloue ses structures avant que l'utilisateur puisse toucher à la mémoire. C'est pour ça que dans Driver.swift, les adresses 0xf800 fonctionnent immédiatement.

📐 Tailles des répertoires

L0 (racine)

1 répertoire · 4 entrées · index sur 2 bits

Stocké à l'offset 0x44 de la frame 0.

L1

Jusqu'à 4 répertoires · 8 entrées · index sur 3 bits

Alloué dynamiquement via kalloc(16).

L2

Jusqu'à 32 répertoires · 8 entrées · index sur 3 bits

Contient des PTE (feuilles de l'arbre).

Offset

8 bits · 0-255

Position dans la frame de 256 octets.

💡 Pourquoi 3 niveaux ? Parce que 22 × 23 × 23 = 28 = 256 pages possibles.
256 pages × 256 octets = 65536 octets = 64 Ko d'espace virtuel. ✓

🧠 À quoi servent les champs ?

PTE.frame Numéro de frame. Si p=1 → frame en RAM. Sinon → slot en mémoire secondaire.
PTE.p / a a=présent, p=en RAM. Les deux sont mis à 1 ensemble par isPresent.
FD.r Référencée ? L'algo de vol met ce bit à 0 à chaque passe, puis regarde qui n'a pas été re-touché.
FD.p Pinnée ? Si oui, JAMAIS évincée (frame 0 du kernel par ex).
FD.br Liste des PTE qui pointent vers cette frame. Sert à mettre à jour les PTE quand on swap.

✏️ Ton exercice : implémenter mmap


      

        🎯 Objectif
        Réserver une nouvelle plage contiguë d'adresses virtuelles et mapper chaque page de cette plage.
      


      
📜 La signature (déjà écrite dans Machine.swift)

      
public mutating func mmap(
  byteCount: Int,
  nearby hint: VirtualAddress,
  for ps: PagePermissions
) -> VirtualAddress? {
  // TODO
  nil
}


      
🔑 Ce que dit la spec (en clair)

      
    
        
  • byteCount : combien d'octets tu veux. Il faut arrondir en pages.
    • 
        
  • hint : une adresse suggérée. Si non-nulle, essaie de mapper près d'elle. Si nulle, choisis toi-même.
    • 
        
  • ps : permissions (.read, .write, .execute).
    • 
        
  • Retour : l'adresse du début, ou nil si échec (mémoire pleine, etc.).
    • 
      


      
🧩 Plan suggéré (déplie étape par étape)


      

        Étape 1 — Calculer le nombre de pages
        
let pages = (byteCount + 255) / 256
// 256 octets par page → arrondi supérieur
// ex: 1 octet → 1 page, 256 → 1 page, 257 → 2 pages

      


      

        Étape 2 — Trouver une adresse de départ
        
Deux cas :

        
    
          
  • Si hint.isNull : parcours l'espace virtuel de 0x0000 à 0xff00 pour trouver un trou assez grand.
    • 
          
  • Sinon : aligne hint sur une frontière de page, et cherche un trou à partir de là.
    • 
        

        
// Rappel : page() te donne l'adresse alignée
let start = hint.isNull ? 0x0000 : hint.page()

      


      

        Étape 3 — Vérifier que la plage est libre
        
Appelle translate() (sans fault handler) sur chaque page candidate. Si ça renvoie nil → c'est libre.

        
for i in 0 ..< pages {
  let va = VirtualAddress(rawValue: candidate + UInt16(i << 8))
  if translate(va, for: [.read]) != nil {
    // occupé → cherche ailleurs
  }
}

      


      

        Étape 4 — Mapper chaque page
        
Appelle allocate() sur chaque adresse de page. Si une seule échoue, retourne nil.

        
for i in 0 ..< pages {
  let va = VirtualAddress(rawValue: base + UInt16(i << 8))
  guard allocate(va, for: ps) != nil else { return nil }
}
return base

      


      

        🪤 Pièges classiques
        
    
          
  • Ne pas aligner sur 256 ! Une page commence toujours sur un multiple de 256.
    • 
          
  • Oublier isNull : hint=0x0000 veut dire « choisis toi-même ».
    • 
          
  • Déborder : base + pages*256 doit rester < 0x10000.
    • 
          
  • Ne pas gérer l'échec : si une page échoue, il faut rollback (mais le kernel ne fournit pas de munmap… à toi de voir).
    •
