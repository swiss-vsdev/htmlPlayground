ÉTAPE 02 / 17

Adresses virtuelles vs physiques

Un processus ne voit JAMAIS les adresses physiques. Il manipule des adresses virtuelles, et la MMU fait la traduction.

🌐 Adresse virtuelle

Ce que le processus manipule. Il croit avoir un grand tableau contigu de 0 à une taille max.

🔌 Adresse physique

L'adresse réelle dans la RAM. Visible seulement par le kernel et la MMU.

Le flux de traduction

Processus → Adresse virtuelle → MMU → Adresse physique

Pourquoi cette abstraction ?

🔒 Sécurité

Un processus ne peut pas lire/modifier la mémoire d'un autre.

🧩 Simplicité

L'app voit un tableau contigu, pas la RAM fragmentée.

🎯 Isolation

Le kernel et les autres processus sont protégés.

ÉTAPE 03 / 17

MMU : Base & Limit

Premier mécanisme de protection. Simple et efficace : deux registres par processus.

Les deux registres

📐 Limit register

Adresse virtuelle maximale autorisée. Au-delà → exception.

📍 Base register

Offset ajouté à l'adresse virtuelle pour obtenir l'adresse physique.

La règle de traduction

si adresse_virtuelle ≤ limite :
    adresse_physique = base + adresse_virtuelle
sinon → exception (segmentation fault)
Simulateur MMU
⚠️ Points clés à l'examen
  • La MMU ne garde aucun historique — elle applique les règles à chaque accès.
  • L'OS configure base et limit pour chaque processus.
  • Le kernel peut s'autoriser limit = max et base = 0.
  • User space = adresses basses · Kernel space = adresses hautes.

ÉTAPE 09 / 17

Pagination

Mémoire organisée en pages de taille fixe (4 KB), mappées sur des frames physiques.

🎯 Le gain principal

Aucune fragmentation externe ! Toutes les pages ont la même taille, donc n'importe quelle page peut aller dans n'importe quelle frame libre.

Table de traduction

Une adresse virtuelle = préfixe (indices dans les tables) + suffixe (offset dans la frame).

Décomposition de l'adresse 0xb2b4

Adresse 0xb2b4 en binaire :
L0: 10 L1: 110 L2: 010 offset: 10110100
Page walk pas à pas
Clique sur "Étape suivante" pour commencer le page walk.

Data structure : Page Table Entry (PTE)

Chaque PTE contient :

  • Adresse physique de la frame ou position swap
  • Bit de validité — page présente en RAM ?
  • Bits de permissions — R / W / X
  • Bit accessed — accédée récemment ?
  • Bit dirty — modifiée depuis le dernier swap ?
⚠️ Cas à connaître
  • Shortcut — une table peut avoir un raccourci direct vers une frame
  • Dead end — entrée = 0xdead → adresse invalide → segfault

Heap : brk vs mmap

Deux mécanismes pour allouer dans le heap. Chacun ses avantages.

📍 brk — syscall #214

Déplace le program break, la fin du segment de données.

brk(NULL)        // lit l'adresse
brk(x + 8192)    // +8 KB

Simple, rapide Fragment, concurrence

🗺️ mmap — syscall #222

Plus général : mappe des fichiers ou de la mémoire anonyme.

mmap(addr, len, prot,
     flags, fd, offset)

Grandes allocs, protections Plus lourd

📋 3 exigences d'un allocateur
  1. Suivre les régions libres et occupées
  2. Supporter la libération dans un ordre arbitraire
  3. Supporter la réutilisation d'une région libérée

ÉTAPE 16 / 17

Flashcards express

Clique sur chaque carte pour la retourner. Reviens-y plusieurs fois avant l'examen.

Question
Différence fragmentation interne vs externe ?
Réponse
Interne : gaspillage DANS un bloc alloué (partition fixe).
Externe : trous ENTRE les blocs (allocation dynamique).
Question
Formule Base + Limit ?
Réponse
Si VA ≤ limit :
PA = base + VA
Sinon : exception (segfault).
Question
Que se passe-t-il lors d'un page fault ?
Réponse
3 cas :
1. Jamais accédée → lazy alloc
2. En swap → ramener du disque
3. Permissions invalides → segfault
Question
Pourquoi le TLB est-il crucial ?
Réponse
Sans lui, chaque accès mémoire ferait un page walk complet (plusieurs accès RAM). Avec : quasi-instantané.
Question
brk vs mmap ?
Réponse
brk : simple, contigu, mais fragment.
mmap : fichiers + protections + grandes allocs, mais plus lourd.
Question
Segmentation vs pagination ?
Réponse
Segmentation : unités logiques, permissions fines.
Pagination : blocs fixes 4 KB, aucune fragmentation externe.
Question
Bit dirty : à quoi ça sert ?
Réponse
Indique si la page a été modifiée.
Si non → pas besoin de la réécrire sur disque (write-back optimization).
Question
Pourquoi ASLR ?
Réponse
Randomise le début de stack et heap pour rendre les attaques mémoire (buffer overflow, ROP) plus difficiles.
